# Unagikuma

<p align="center"><img src="docs/images/IMG_8128.jpeg" alt="Unagikuma" width="240"></p>

**또 하나의 가동 상태 점검 도구: u(ptime) + nagi(os) + kuma(Uptime Kuma).**

쉽고 간편한 셀프 호스팅 모니터링: 웹사이트나 서버가 다운되면 바로 알 수 있고, 알림 폭탄은 없습니다.

## Unagikuma를 써야 하는 이유

- **약 30초면 준비 완료.** 파일 하나를 내려받아 실행하고 브라우저를 열면 끝입니다.
- **파일 하나, 따로 설치할 것 없음.** Linux, macOS, Windows, FreeBSD에서 동작합니다.
- **중요한 것을 확인합니다.** 웹사이트, 서버, 포트, ping, DNS, SSL 인증서, 도메인 만료일.
- **늘 쓰는 곳으로 알림.** 이메일, Telegram, Slack, Discord, Feishu, DingTalk, WeCom, 웹훅 등.
- **문제는 하나, 알림 폭탄은 없습니다.** 내 쪽 네트워크가 끊기면 Unagikuma가 이를 알아차리고 모니터마다 알림을 보내지 않습니다.
- **상태 페이지**로 사용자에게 언제나 상황을 알려 줍니다.
- **함께 성장합니다.** 필요해지면 웹 화면의 참여 코드로 두 번째 컴퓨터나 클러스터 전체를 1분 만에 추가할 수 있습니다.
- **옮겨 오기 쉽습니다.** Uptime Kuma나 Nagios의 모니터를 가져올 수 있습니다.
- **내 언어로.** 화면은 15개 언어를 지원합니다.

## 빠른 시작

**1.** [Releases](https://github.com/githubflyideas/unagikuma/releases/latest)에서 내 시스템에 맞는 파일을 내려받아 압축을 풉니다.

**2.** 실행합니다:

```sh
./unagikuma
```

Windows에서는 `unagikuma.exe`를 실행합니다.

**3.** 브라우저에서 http://localhost:8077 을 열고 관리자 계정을 만듭니다.

**4.** **모니터 추가**를 누르고 웹사이트 주소를 입력하면 끝입니다.

> 다른 컴퓨터에서 여나요? `http://<서버-주소>:8077`에 접속해 프로그램이 처음 시작할 때 보여 준 **설정 토큰**을 입력하세요.

## 한 대, 두 대, 클러스터

> **두 마리 토끼를 다 잡습니다.** 대부분의 모니터링 도구는 둘 중 하나를 고르라고 합니다. 시작은 쉽지만 한 대에 묶이는 작은 도구, 아니면 확장은 되지만 데이터베이스와 에이전트 설치에 오후를 다 쓰는 큰 도구. Unagikuma는 둘 다입니다. 한 대의 컴퓨터에서 파일 하나로 시작하고, 더 필요하면 다른 컴퓨터를 합류시키면 됩니다. 같은 프로그램, 같은 화면, 옮길 것은 없습니다.

Unagikuma는 무엇보다 한 대의 컴퓨터를 위해 만들어졌습니다. 검사, 알림, 상태 페이지, 기록이 모두 한 대에서 동작합니다. 컴퓨터를 더하면 보는 관점이 늘어날 뿐입니다.

### 한 대: 바로 사용

파일을 실행하고 모니터를 하나 추가하면 끝입니다. 데이터베이스도, 에이전트도, 두 번째 서버도 필요 없습니다. 대부분의 사람이 이렇게 쓰며, 한 대만으로 충분합니다.

![개요: 이 컴퓨터에서 각 대상까지 어디가 끊겼는지](docs/images/overview.png)

### 두 대: 각자 독립적으로 감시

다른 사무실이나 다른 호스팅 업체처럼 다른 곳에 두 번째 서버를 둡니다. 첫 번째 서버에서 **설정 › 노드 › 참가 코드** 를 열고, 두 번째 서버에서 **설정 › 노드 › 클러스터 참가** 를 열어 코드를 붙여 넣습니다. 두 번째 서버는 곧바로 설정 사본을 받아 즉시 검사를 시작합니다.

- **두 서버가 각자 검사하고 각자 알립니다.** 한쪽이 멈춰도 다른 쪽은 계속 동작하며 알림을 보냅니다.
- **추측하지 않습니다.** 두 서버가 서로를 볼 수 없게 되면 어느 쪽이 끊겼는지 알 수 없으므로, 어느 쪽도 상대가 죽었다고 선언하지 않습니다. 둘 다 계속 스스로 검사하고 알립니다.
- **모든 메시지에 보낸 사이트 이름이 붙습니다** (`[Tokyo] …`). 알림이 어디서 왔는지 항상 알 수 있습니다.

### 클러스터: 모든 사이트를 한 장의 그림으로

같은 방법으로 원하는 만큼 사이트를 추가하세요. 각 사이트는 여전히 스스로 검사하고 알리므로, 메인 서버를 포함해 어떤 사이트가 빠져도 모니터링은 멈추지 않습니다. 클러스터가 더해 주는 것은 전체 그림입니다. 모든 모니터와 모든 알림에 다른 사이트들이 지금 보고 있는 결과가 함께 표시됩니다.

![장애 중인 모니터와 사이트별 결과](docs/images/detail-sites.png)

- **"모든 곳에서 다운"인가, "여기서만 다운"인가?** 각 사이트의 관측 결과를 보면 서비스가 정말 다운됐는지, 네트워크 경로 하나만 끊겼는지 한눈에 알 수 있습니다. 오래된 결과는 따로 표시됩니다.
- **조용해진 사이트는 한 번만 알립니다.** 1분 후(조정 가능)에 알리고, 돌아오면 복구 알림을 보냅니다. 메인 서버를 다시 시작해도 "사이트에 연결할 수 없음" 메시지가 쏟아지지 않습니다.
- **설정 변경은 몇 초 안에 모든 사이트에 전달됩니다.** 각 사이트는 그 사무실의 라우터처럼 자기만의 모니터도 가질 수 있습니다.

![노드 페이지: 각 사이트의 상태, 왕복 시간, 설정](docs/images/nodes.png)

## 알림 폭주: 문제 하나에 메시지 하나

케이블 하나 끊어졌다고 백 번 호출하는 모니터링 도구는 결국 음소거되고 쓸모없어집니다. Unagikuma는 알림 폭주를 막아야 할 결함으로 다룹니다.

- **먼저 내 네트워크.** 이 컴퓨터 자체의 인터넷 연결이 끊기면, 모든 대상이 함께 실패했다는 것을 알아차리고 모니터마다가 아니라 네트워크에 대해 메시지 하나만 보냅니다. 연결이 돌아오면 보류했던 모니터를 조금씩 다시 검사한 뒤에 보고합니다.
- **부모가 먼저, 자식은 나중.** 호스트가 다운되면 그 위의 서비스를 하나하나 알리지 않습니다.
- **채널마다 1분에 최대 3건.** 그 이상은 1분이 끝날 때 가장 심각한 것부터 한 건의 요약으로 묶입니다. 새 문제에는 별도 몫이 있어 리마인더 때문에 늦어지지 않지만, 서비스 백 개가 함께 실패해도 받는 것은 메시지 백 개가 아니라 요약 하나입니다.
- **좋은 소식은 붙잡지 않습니다.** 복구와 에스컬레이션은 항상 즉시 나가므로, "이제 손 놓아도 된다"는 메시지를 기다릴 일이 없습니다.
- **플래핑은 요약합니다.** 올라갔다 내려갔다 하는 서비스는 횟수가 붙은 하나의 사건으로 보고됩니다.
- **계획된 작업은 조용히.** 점검 시간 동안에는 작업하겠다고 한 대상에 대해 알리지 않습니다.

모든 한도는 **설정 › 조정 값** 에서 조정할 수 있습니다.

## Uptime Kuma에서 옮겨 오기

Uptime Kuma를 멈춘 뒤 먼저 확인합니다(아무것도 바뀌지 않음):

```sh
./unagikuma import kuma --dry-run /path/to/uptime-kuma/data/kuma.db
```

문제가 없으면 가져옵니다:

```sh
./unagikuma import kuma /path/to/uptime-kuma/data/kuma.db
```

보고서에는 가져온 항목, 확인이 필요한 항목, 가져오지 못한 항목과 해야 할 일이 나옵니다. `data/import-reports/`에도 저장됩니다. 다시 실행하면 새 항목만 추가됩니다.

## Nagios에서 옮겨 오기

`nagios.cfg`를 지정하고 먼저 확인합니다(아무것도 바뀌지 않음):

```sh
./unagikuma import nagios --dry-run /etc/nagios4/nagios.cfg
```

문제가 없으면 가져옵니다:

```sh
./unagikuma import nagios /etc/nagios4/nagios.cfg
```

보고서에는 가져온 항목, 확인이 필요한 항목, 가져오지 못한 항목과 해야 할 일이 나옵니다. `data/import-reports/`에도 저장됩니다. 다시 실행하면 새 항목만 추가됩니다.

## 비밀번호를 잊으셨나요?

Unagikuma가 실행 중인 컴퓨터에서:

```sh
./unagikuma reset-password admin
```

새 비밀번호를 두 번 입력합니다(화면에 표시되지 않음). 대신 무작위 비밀번호를 받으려면 `--generate`를 붙이세요.
