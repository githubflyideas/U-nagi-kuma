# 各站独立监控：升级与运维契约

## 运行语义
- 配置只有一个人工指定的主站；没有自动选举。断主后继续使用最后一份配置，修改共享配置须先人工晋升。
- 每个完整服务器持续调度分配给本站的监控，独立阈值、告警、恢复、ACK、静默、队列和审计链；不投票、不跨站去重。
- 观测表只提供上下文，约每两秒拉取源站增量；旧于三个检查间隔标记 stale。未收到的数据不妨碍本站告警。
- 信息表不是跨站事件状态机。历史导入是明确标记的快照，不承诺其 ACK/恢复状态实时更新；操作发回原站，原站离线明确失败，绝不代改镜像。
- 配置/策略复制包含通知密钥及联系人，完整站点和站点管理员属于高信任边界。

## 身份和证据
- 事件规范键为 `source_node:db_epoch:original_id`；本地数值 ID 只作数据库索引/本站 API 路径。
- 每个站点有独立持久 TLS 身份。角色晋升不更换该身份，也不复制主站事件库、ACK、队列或审计链。
- 证据、通知、决策和归档带来源/epoch；导入审计保留原 hash。只保证各源内的序列/哈希链，不保证跨站绝对时间总序。
- 历史默认只查本站；`site=站点名` 查对应归档，`site=*` 显式查所有站点。远站旧图表只用其保留的原始结果，不偷用本站聚合。
- 原始结果、事件、已关闭事件、ACK、证据和源审计受保留期限制；保留期外审计只验证留下的连续后缀，不声称覆盖已删除前缀。

## 从旧版升级
1. 停止旧程序，保存加密完整备份（含历史）及原始配置，保留单独的回退副本。新 schema 不能直接用旧二进制打开。
2. 先升级配置主站，再升级所有完整服务器，连通时等候一次成功的配置/密钥/联系人同步与站点身份分发，再测试断主。旧版混跑不作为支持模式。
3. 旧 probe-only `agent` 没有独立数据库和通知状态，启动将明确拒绝；须用独立数据目录运行完整 `server`，经集群加入流程获取配置，不能直接把无状态代理当独立站点。既有 NODE 不允许任意同名覆盖：先保存其区域、分组、监控范围，停止旧代理；在主站维护窗口内暂时移除该 NODE 的范围引用及记录，生成加入码让完整服务器按原站点名加入，再恢复原范围/区域/分组。也可用新站点名加入后一次性迁移范围。不要让旧代理与新服务器并行认领同一身份。
4. 一次性迁移给旧事件补来源身份；旧集群投票/地域事件仅归档，不伪造恢复，撤掉对应旧队列项并重新采样本站。旧单机事件的 ACK 和队列继续保留。
5. 旧版本忽略的多接收站 PUSH 配置归一为旧主站接收，原配置保存为 `.before-per-site`；今后 PUSH 必须明确且仅有一个接收站。单接收站配置保持不变。
6. 观察到源站证书指纹和 N 行观测后，再演练隔离。若无配置副本或新身份尚未分发，应明确视为升级未就绪，而不是临时退回投票。

## 恢复、晋升和 ACK
- 完整恢复必须停掉原实例。加密备份保存独立站点身份；恢复流程写入换代标记，下次启动为未来事件/观测生成新 DB epoch，历史键不改。
- 不要同时运行同一站点身份的两个恢复副本；epoch 区分数据库世代，不是允许复制同一物理站点身份的机制。
- 恢复不带历史的备份时没有被省略的历史可供证明；需要完整证据链请保留独立完整备份和外部审计 head。
- 手工晋升只转移配置写权限。原站回来后作为相同物理站点重新加入并持续监控，不能自动清掉本站事件。
- a 恢复/ACK 不代表 b 恢复/ACK；远站 ACK 请求只作用于那个源事件。分区期间不能保证一键立即停止所有站通知。
- 消息保留创建时的冻结观测快照，不用后来补齐的表改写已排队的告警/恢复。

## 回归入口
`sudo python3 scripts/per-site/netns-regression.py --nodes 3 --rig /workspace/r6 --binary /workspace/r7/uk-per-site`

2/5 站分别指定 `--nodes 2/5 --rig /workspace/r7`。复用现有 r7 路由拓扑脚本，但使用独立 `uksN*` 命名空间及新的结果目录，不覆盖旧测试数据。输出包含逐项 PASS/FAIL、hook 和源站日志。

晋升会保留旧主站的物理 NODE 及其 nodes= 范围，只迁移配置权威和代理认证哈希，不覆盖本地运行态。旧主重新加入使用一次性加入码，不改站点名称；既有 NODE 的分组、区域等配置不覆盖。若旧主站名与非 NODE 记录重名，先消除名称冲突再晋升，不能静默回退为空配置。

历史 rounds 表升级为不回收的自增 ID，保留原 rowid，防止保留期清空后重用已导出的来源 ID/游标。该迁移重建历史表和索引：首次启动前备份，预留至少一份 history.db 大小的额外磁盘空间；大历史库需安排维护时段。
